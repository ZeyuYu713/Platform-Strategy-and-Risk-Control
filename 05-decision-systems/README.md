# 05｜Risk Decision Systems：策略决策系统

## 一、策略决策系统承担什么工作？

策略的最终形态不是一段模型代码，而是一套能够在业务请求发生时，**稳定、及时、合规、可审计地做出动作**的产品与技术流程。

在风控业务中，系统可能需要在一次支付、登录、内容发布或优惠领取请求发生时读取合法可用的信息，输出一种明确动作，并留下可以复盘的证据与版本。

建议把决策过程拆为六个逻辑层次；它们是架构抽象，不代表实际系统必须严格顺序执行。

~~~mermaid
flowchart TD
  A["事件接入与身份/权限检查"] --> B["特征与上下文"]
  B --> C["规则判断、模型评分"]
  C --> D["策略编排与冲突仲裁"]
  D --> E["放行/验证/人工审核/限制"]
  E --> F["决策日志与反馈"]
  F -. "经授权的反馈" .-> C
~~~

## 二、规则引擎、模型服务和策略引擎如何区分？

| 模块 | 核心职能 | 需要重点关注 |
| --- | --- | --- |
| Feature Service | 提供决策时可用的特征 | 数据延迟、缺失、权限、质量 |
| Rule Engine | 执行确定性条件与政策规则 | 优先级、冲突、版本、可解释性 |
| Model Scoring | 估计风险/质量/相关性 | 校准、漂移、模型版本、异常回退 |
| Decision Policy | 合并证据并选择动作 | 风险成本、动作可用性、公平与合规 |
| Action Service | 执行验证、审核、限制等 | 幂等性、超时、状态一致性 |
| Audit & Feedback | 留痕、申诉、反馈与复盘 | 证据权限、保留期限、结果延迟 |

**模型分数不是风控结果；风控结果也不是天然的动作。** 例如某模型输出风险概率 0.7，是否直接拒绝，还要考虑分数校准、交易损失、验证方式和制度约束。

## 三、策略编排必须回答的工程问题

### 1. 规则优先级与冲突处理

如果两个策略同时对同一对象给出不同动作，系统必须有明确决策仲裁：法律/安全底线、证据优先级、人工授权、动作严重度与可逆性，不能靠“最新配置覆盖前面配置”的偶然执行顺序。

### 2. 决策时延

实时支付流程与内容发布后的异步审核，允许的延迟不同。实时策略应明确 P50/P95/P99 时延，异常时是否补充验证、降级、暂缓或转人工。**故障时全放行还是全拦截**都可能造成严重后果，不存在跨业务通用的安全答案，需要场景化风险评估与合规审查。

### 3. 规则、模型与配置发布

每次策略版本应有唯一 ID、变更说明、批准权限、灰度范围、可逆回滚和观察窗口。核心变更要可追溯，不应允许未经授权的个人直接改变高风险处置规则。

### 4. 数据隐私、最小必要与公平性

特征获取必须符合数据治理与适用法律的要求。对敏感信息使用、跨境传输、日志保留及人工审核权限设置应遵守最小必要原则。监控不同受影响群体的误判差异，在适当场景下评估公平性，不将模型分数当作无需解释的“客观事实”。

## 四、人工审核是系统中的一个有容量的环节

假设每天有 12,000 条请求需要人工复核，50 名审核人员每天各能完成 200 条，名义审核能力为 10,000 条/天。

若到达与处理能力长期稳定，则每日新增待审积压约 2,000 条。这里没有计入排班、复杂度、退单、返工和不均匀到达，实际可能更严重。

产品经理不能仅凭“送人工最安全”来设计策略。应考虑：
- 不同风险程度的审核优先级；
- 审核所需证据、操作权限与时间；
- 自动审核的证据标准和可复核性；
- 对正常用户等待与交易转化的影响；
- 申诉和纠错队列是否独立。

## 五、产品需求：设计一个风控策略配置后台

假设风控策略人员希望在不改代码的情况下调整合法可配置的策略。后台应具备：

**策略创建与版本控制**：目标事件、作用范围、可用特征、条件、动作、负责人和生效时间。

**影响预估**：离线回放下的命中样本量、风险预测、潜在误报数量及数据限制，注意回放不是因果实验。

**发布流程**：权限审批、灰度比例、自动回滚规则、变更单、发布记录。

**诊断能力**：请求 ID 下的版本、模型调用结果、规则命中记录、动作结果、时延及失败原因；个人信息应按权限掩码。

**申诉与复核**：人工覆盖有授权范围和留痕，异常复核可反馈策略缺陷。

## 六、面试题：模型服务突然超时怎么办？

参考思路：先界定风险事件与故障范围，检查延迟、错误率、受影响区域和版本；启动事先审批的降级预案，并对高风险与普通场景采用不同的安全动作；确保决策日志完整和用户权益可救济；恢复后核对误判、漏判、交易损失及申诉，将事故转化为监控与预案改进。

不要未经场景限定地说“模型失败后所有请求放行”或“所有请求拒绝”。
