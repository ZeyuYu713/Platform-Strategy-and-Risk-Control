# 01-A｜策略产品设计的完整方法

## 一、不要从“做个规则”开始

一个可交付的策略 PRD 首先要区分：业务问题、被决策对象、可执行动作、收益和成本。以下以“降低异常交易损失”为例，贯穿展示。

### 1. 业务问题与范围

现象：某业务的交易风险损失上升。但损失上升可能由交易额增加、客户结构变化、欺诈方式变化、确认延迟或错误计算导致。

建议先定义：
- 时间：观察哪一周或哪一月，结算和回传是否完成？
- 对象：什么地区、场景、商户、用户层级？
- 口径：欺诈损失额、损失率、拒付、举报、确认欺诈标签是否混淆？
- 单位：每笔交易、每千笔、每用户，还是交易额归一化？
- 目标：降低损失率，不是机械减少所有交易。

### 2. 决策对象与可用数据

对象是订单、用户、广告请求还是视频？决策发生在请求前、实时交易中还是事后审核？数据可用性与延迟会影响方案设计。

例：实时交易风控只能使用**决策时已经可获得的数据**。把 7 天后的拒付结果作为当下特征属于标签泄漏，线下精度再高也不能部署。

### 3. 策略空间与可执行动作

设计离散动作集合：

$$
A=\{\text{放行},\text{补充验证},\text{人工审核},\text{拦截}\}
$$

动作有不同成本。审核可能造成队列和等待，补充验证会带来转化损失，拦截会损失正常交易。单纯最大化风险召回不一定最优。

### 4. 目标函数和护栏

例（假设口径）：

$$
\min \left[C_{\mathrm{fraud}}+C_{\mathrm{false\ positive}}+C_{\mathrm{review}}+C_{\mathrm{delay}}\right]
$$

同时施加约束：正常交易误拦率不超过产品允许的阈值；审核队列不超容量；关键链路延迟不超服务目标。

权重和成本不是凭主观感觉指定的常数。需要业务估算，或通过实验对不同方案的收益与代价进行敏感性分析。

### 5. 分层策略，不是一个全局阈值

若不同风险场景差异很大，可以先在合法、业务合理的维度建立分层，比较不同策略的校准与损失。不应为追求指标而使用受保护或不适当的个人特征进行歧视性决策。

风控可采用“低风险直通、中风险补充验证、高风险人工审核或限制”的设计思想，**但具体触发条件应基于合法合规的风险证据，而不是一套可公开通用的固定阈值**。

### 6. 实施与验证

上线前：检查日志完整性、规则冲突、特征缺失、模型回退、审核容量、数据隐私、申诉流程。

上线中：小范围灰度、分层监控、自动止损、版本留痕、人工复核通道。

上线后：比较主指标与护栏，分析新老用户、正常与异常交易表现；注意策略干预后的标签可能变得不可观察。

## 二、一个策略 PRD 的参考骨架

| 字段 | 要填写的内容 |
| --- | --- |
| 背景 | 哪个业务问题、基线数据、影响范围 |
| 目标 | 主指标、目标改变量、统计窗口 |
| 对象 | 决策单元、场景、触发时点 |
| 数据 | 允许使用的特征、更新频率、缺失值 |
| 机制 | 规则、模型、阈值、优先级、冲突处理 |
| 动作 | 放行、推荐、降权、审核、限制等 |
| 风险 | 误杀、延迟、偏差、反馈、隐私与合规 |
| 实验 | 处理单元、对照组、主指标、护栏 |
| 交付 | 接口、日志、权限、后台、回滚方案 |
| 复盘 | 实验结论、因果边界、后续改进 |

## 三、为什么“把阈值调到最优”很危险？

风险标签可能存在延迟或选择偏差；如果被拦截的交易从未发生，就无法简单观察其真实风险。内容分发也是一样：低曝光内容缺乏反馈，不代表它一定低质量。广告竞价里未获得展示机会的广告也缺乏真实用户响应。

因此，策略训练数据往往由旧策略筛选过。这类“只看被旧策略留下的样本”问题称为**选择偏差 / 反馈偏差**。需要谨慎评估随机化探测、人工抽检、延迟标签修正等方法是否适用与合规。

## 四、面试答案结构

题目：“让你优化一个内容风控策略，怎么做？”

可按“业务口径 → 误判分层 → 机制与动作 → 线上验证 → 长期治理”讲：

先定义违规类型、风险程度和处理要求；再拆出模型识别、规则处置、人工复核以及申诉的环节；对同口径的 Precision、Recall、FPR、损失和申诉恢复率建立基线；通过分层策略改变处置动作，设置正常内容覆盖和时延护栏；最后灰度验证、复盘误判案例和数据漂移，预留回滚及透明申诉渠道。

**不能只说“让算法提高准确率”**：因为模型指标可能和实际业务损失、用户权益不一致。
